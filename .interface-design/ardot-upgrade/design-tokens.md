# PSX UI 升级 · Ardot 设计参数快照

本文档是从 Ardot 设计稿提取的 UI 参数基准，供 PSX 桌面终端（WPF + WebView2）Agent Shell 视觉升级开发使用。所有色值均由 MCP 返回的 0~1 浮点 r/g/b/a 四舍五入换算为 `#RRGGBB`（a<1 时标注 `@百分比`）。

## 1. 基准信息

- 设计文件：`https://ardot.tencent.com/file/723296751630711`
- 文件 ID：`723296751630711`
- 提取日期：2026-09-10（分支 `codex/ui-ardot-upgrade`）
- 变量集：`PSX Flat`（set id `2:19`，Light/Dark 双模式）

### 变量 ID 映射（画板内 `$2:xx` 引用）

`$2:20`=surface、`$2:21`=sidebar、`$2:22`=chrome、`$2:23`=border、`$2:24`=text、`$2:25`=muted、`$2:26`=selected（均为变量集 `2:19` 内的变量）。

## 4. 五套主题参数表

通用结论（适用于全部五套，除非特别注明）：

- 文字/图标前景在浅色系三稿（基础浅、草原绿、羊皮纸黄）全部引用 `PSX Flat` Light 变量或固定灰：标题 `#26292E`、muted `#6E737A`、图标 `#666666`、rail 激活图标/历史标题图标 `#1E1E1E`、终端 `>_` 图标 `#555555`、关闭 ×（激活 `#888888` / 非激活 `#999999`）。
- 深色系两稿（Vercel 黑、炭黑）改用字面灰：正文 `#FAFAFA`、muted/非激活图标 `#A3A3A3`、关闭 ×（激活 `#888888` / 非激活 `#A3A3A3`）。激活 Tab 背景在 CLI 列与 Agent 列均为 `#3D3D3D`；激活 Tab 标题在 CLI 列引用 `$2:20`（surface）、在 Agent 列为字面 `#FAFAFA`。
- CLI 列命令条（Command Bar）在五稿中均为 `#292B2E`、圆角 3，不随主题变化（功能件）。
- Composer 阴影在五稿中均为 `rgba(0,0,0,0.06)`，偏移 0/5，模糊 8，扩散 1。
- 全部描边均为 1px INSIDE。

## 7. 冲突与存疑项

1. **`tabHeight` 变量 = 36 vs 画板 40px**：变量集 `PSX Flat` 的 `tabHeight` 为 36，但所有画板 Tab 栏实测高度均为 40px（`8:246` 等）。以画板 40px 为准，变量值疑为旧版遗留。
2. **【已解决】草原绿 Composer 背景色**：锚点记录 `#ECF4DC`，实测节点 `8:830` fill 为 r 0.902 / g 0.973 / b 0.824 → 230/248/210 = **`#E6F8D2`**（早前换算曾误写为 `#ECF4D2`，复审时重读节点纠正）。实现以实测 `#E6F8D2` 为准。
3. **【已核实】深色稿激活 Tab 颜色（CLI 列与 Agent 列均为 `#3D3D3D`）**：已逐列复核四张 Tab 条——Vercel 黑 CLI 列 `8:1317`→激活 Tab `8:1358`、Vercel 黑 Agent 列 `8:1328`→激活 Tab `8:1379`、炭黑 CLI 列 `8:1821`→激活 Tab `8:1862`、炭黑 Agent 列 `8:1832`→激活 Tab `8:1883`，背景全部为 `#3D3D3D`（r/g/b 0.2392），两列颜色相同、无差异。两张深色稿中不存在任何 `#E8E8E8` 的 Tab 节点（选中行/搜索框等其它候选节点亦无此值；最接近的亮灰是文字 `#FAFAFA`）。**结论：`#E8E8E8` 是用户指定的实现值（深色模式终端列选中 Tab 用亮灰白），画板未体现；实现时深色主题终端列激活 Tab 取 `#E8E8E8`（用户指定），设计稿值 `#3D3D3D` 仅作存档。**
4. **【已核实，范围收窄】CLI 列激活 Tab 标题引用 `$2:20`**（`8:1430`/`8:1934`）：该变量随模式解析——Light=`#FFFFFF`（深底白字，可读），Dark=`#0C0C0D`（`#3D3D3D` 底上近黑，几乎不可读）。仅 CLI 列激活 Tab 使用该变量；Agent 列激活 Tab 标题为字面 `#FAFAFA`（`8:1457`/`8:1961`），无此问题。实现时 CLI 列激活 Tab 标题应固定为浅色文字，不绑定 Dark 模式变量。
5. **Composer 边框透明度不一致**：基础浅/草原绿/羊皮纸黄为 @70%，Vercel 黑（`#404040`）/炭黑（`#4A4F57`）为 @100%。按稿实现，不取平均。
6. **【已解决，待设计确认】草原绿两处渐变起始位置不一致**：Rail `8:790` 首色标 pos≈0.169，历史面板 `8:791` 首色标 pos≈0.094（终色标均为 1.0，色值相同）。PSX 外壳由始终加载的 shell 用 `background-attachment: fixed` 绘制一条共享渐变（保证 rail 与历史面板坐标连续、滚动不带动渐变），无法同时表达两个位置。**统一取历史面板值 9.39%**（历史面板是渐变的主要可见面，rail 仅 40px 宽，差异不可感知），通过 `[shellTheme] sidebarGradientFromStop=9.39` 配置承载，位置参数不再丢失；若设计要求 rail 用 16.89%，需改为双表面各自渐变并接受接缝色跳变。
7. **【已核实】「760px 阅读列」仅在单列稿出现，且为居中固定宽**：单列稿 `8:1` 中 Agent 工作台（`8:13`，宽 1259，内边距 24 → 内区 1211px）内有 `Reading Column Wrapper`（`8:235`，1211px），其内 `Reading Column`（`8:236`）实测 **760px 宽、两侧各留白 225.5px 居中**；会话区 `Center Greeting Area`（`8:36`）与 `Composer`（`8:37`，760×80）均在 760px 列内。多列稿无双列对应结构：双列稿 `8:237` 的 Agent 工作台（`8:249`）无 Reading Column Wrapper，内容直接铺满列宽（629.5px，内边距 24 后 581.5px）。**结论：单列布局实现「内容区 + Composer 最大宽 760px 居中」有设计依据（`8:236`）；多列时设计稿为铺满列宽，PSX 现行多列 760px 居中规则与双列稿不符，保留与否需产品决策。**
